# T2Rhythm 5.5.499.1313 — 완료 이력·다운로드 정리·저부하 분석·기록 요약

## 완료한 음악은 다시 처리하지 않기

‘라이브러리 정보 및 가사’는 각 곡의 작업 완료 이력을 영구 저장합니다. 같은 정보·설정으로 확인을 마친 곡은 다음 일괄 작업에서 제외하고, 새 곡이나 제목·아티스트·앨범·장르·길이 등 입력이 달라진 곡은 다시 확인합니다. 앱이 직접 태그를 저장해 수정 시각이 바뀐 것만으로 같은 곡을 다시 처리하지 않습니다.

처리할 곡 수와 전체 보관함 곡 수를 구분해 표시합니다. 처리할 곡이 없으면 시작 버튼을 비활성화하고 완료 안내를 보여 줍니다. 제공처에 일치하는 정보가 없었던 곡도 ‘확인을 마친 곡’에 포함합니다. 다시 조회하려면 펼친 옵션의 **완료한 곡도 다시 확인**을 선택합니다. 작업이 예외로 중단된 곡은 완료 이력으로 기록하지 않습니다.

덮어쓸 항목·제공처·가사 소스 등 작업 정책을 바꾸면 현재 정책으로 다시 확인할 수 있습니다. Wi-Fi 사용 여부와 백업 폴더 변경만으로 완료 곡을 재처리하지 않습니다. 기존 작업의 완료 이력은 실패 항목을 구분할 수 있는 경우에만 이전합니다. 이력은 작업 중복 방지용이며, 음악 정보나 영구 가사를 대신하는 저장소가 아닙니다.

## 실패 다운로드의 파일과 기록 함께 지우기

설정의 백그라운드 다운로드에서 실패·취소 항목의 **실패 파일·기록 삭제**를 누르면 남은 다운로드·이어받기 파일과 작업 기록을 함께 지웁니다. 두 번째 확인창은 표시하지 않습니다. **실패·취소 항목의 파일과 기록 모두 삭제**로 한꺼번에 정리할 수도 있습니다. 삭제 도중 늦게 도착한 작업 콜백이 항목을 되살리지 않게 보호합니다.

진행 중인 작업과 성공한 다운로드는 삭제 대상이 아닙니다. 음원은 앱이 게시 중이던 미완성 파일만 정리하고, 이미 보관함에 저장한 파일은 유지합니다. 모델의 실패한 임시 설치 폴더도 정리하되 정상 설치·복구용 모델은 유지합니다. 파일 삭제가 거부되면 기록을 남겨 다시 시도할 수 있습니다.

## 화면을 쓰고 있어도 조건이 맞으면 조금씩 분석

오디오 분석·추천 학습·장르와 가사 분석·자동 기록 정리는 **충전 중이거나 배터리 90% 이상이고, 기기 부하가 낮을 때** 실행합니다. 화면이 켜져 있거나 사용 중이라는 이유만으로 기다리지 않습니다. 절전 모드, 발열, 메모리 부족, 높은 CPU 사용량이나 실행 지연을 감지하면 작업을 양보하고 나중에 이어갑니다. 과거 버전에서 충전·유휴 조건을 기다리던 작업도 기존 작업 ID를 유지해 이전합니다.

앱 전체의 분석 실행 스레드를 하나로 제한하고 작은 작업 구간마다 쉽니다. Android가 `/proc/stat` 읽기를 허용하지 않으면 앱 CPU·메모리·발열·실행 지연 신호를 사용합니다. 시스템이 백그라운드 실행을 제한하면 조건을 만족해도 바로 실행되지 않을 수 있습니다. 사용자가 시작한 음원·영상·음성 모델 다운로드는 이 분석 조건과 구분합니다.

## 120일 상세 기록, 이후에는 복구 가능한 요약

최근 **120일**은 상세 청취·추천 기록을 보존합니다. 이전 기록은 같은 곡·재생·맥락으로 이어진 청취 구간을 합치고 반복 센서 값을 줄여 보관합니다. 쉬었다가 다시 들은 구간을 연결해 청취 시간을 부풀리지 않습니다. 날짜·시간대·청취량·완청률·최초 완청 시점·취향 변화와 기기·이동·날씨 등 추천에 쓰는 맥락 관계를 유지합니다. 정밀 좌표는 기존 추천이 사용하는 지역 단위로 줄입니다.

추천 학습에는 당시의 특징값·보상·예측값·반응 식별자를 보존해 재학습과 반응 취소가 가능합니다. 오래된 원시 센서 값과 반복된 후보 목록은 줄입니다. **음악 파일·아트워크·가사·실제 좋아요와 취향 재확인 이력은 정리하지 않습니다.** ‘기록 보관 및 자동 요약’에서 보존 정책과 정리 결과를 확인할 수 있습니다.

정리는 하루 주기로 예약하며 첫 실행 후 20분 이후부터 저부하 조건을 확인합니다. 각 회차는 짧게 실행하고 중단 지점부터 재개합니다. 기록 파일은 임시 파일 작성·동기화 후 원자적으로 교체합니다. 이전 원본 기록을 다시 가져와도 합친 구간이 중복 계산되지 않게 식별자를 보존하며, 데이터베이스를 새로 만들어도 요약 파일에서 통계를 복구할 수 있습니다.

백업의 예전 상세 버전은 새 요약본이 같은 기록을 포함하고, 백업에 게시한 파일의 SHA-256이 일치함을 확인한 뒤 정리합니다. 알 수 없는 형식·손상된 파일·더 새로운 기록은 자동 삭제하지 않습니다. 데이터베이스의 빈 페이지는 재사용하며 화면을 막는 전체 재압축은 수행하지 않습니다. 따라서 표시한 절감 용량은 실제 기록 파일 감소량이고 기기 전체 저장 공간과 다를 수 있습니다.

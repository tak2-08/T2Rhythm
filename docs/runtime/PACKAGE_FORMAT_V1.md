# T2Rhythm 기능 패키지 v1 — 검증/적용 기반

2026-10-24. `runtime-core`는 Android에 의존하지 않는 검증/정책 모듈이다. 아직 실제 앱의 실행 경로에 연결하지 않았다. 형식 v1은 개발 중이며 실제 Compose 로딩·리소스 실험 결과에 따라 확정한다.

## 패키지

`.t2module`은 다음 **네 파일만** 담은 ZIP이다. 실행기 APK와 다른 배포물이며 Android 설치기에 전달하지 않는다. 서명이 맞더라도 일반 APK를 이 형식으로 자동 변환하거나 임의 앱을 실행하지 않는다.

| 파일 | 내용 | 압축 해제 크기 상한 |
| --- | --- | --- |
| `manifest.json` | 엄격한 UTF-8 JSON, 아래 필수 필드 전체 | 16 KiB |
| `manifest.sig` | manifest 원문 바이트에 대한 SHA256withRSA 서명 | 1 KiB |
| `content.dex.jar` | 향후 호스트가 로딩할 DEX 패키지 | 192 MiB |
| `notes.md` | 사용자가 설치 전에 읽는 변경 내역, UTF-8 | 128 KiB |

전체 ZIP은 224 MiB 이하로 제한한다. 중복·경로 이동·추가·누락 항목과 디렉터리를 거부하며 압축 해제 파일을 만들지 않고 스트림으로 크기와 해시를 확인한다. 검증 중 아카이브가 달라져도 거부한다. JSON의 중복·알 수 없는·누락된 필드, 잘못된 타입, 소수·정수 초과·후행 문서를 거부한다. 검증 통과를 DEX 문법·클래스 로딩·동작 호환성의 통과로 해석하지 않는다.

## 서명된 manifest

서명은 JSON을 재직렬화한 내용이 아니라 **배포 파일의 정확한 원문 바이트**에 적용한다. 따라서 키 순서·줄바꿈·공백도 서명 이후 바꿀 수 없다. 모든 필드는 필수다.

| 필드 | 타입/의미 |
| --- | --- |
| `formatVersion` | 정수 `1` |
| `moduleId` | 호스트가 허용한 모듈 ID, 예: `t2rhythm.main` |
| `versionCode` | 1 이상의 증가하는 64비트 정수, APK 버전과 별도 |
| `versionName` | 사용자 표시 버전, 1~96자, 제어문자 금지 |
| `signingKeyId` | 공개키의 DER SubjectPublicKeyInfo SHA-256, 소문자 hex |
| `entryPointClass` | `chromahub.rhythm.module.` 아래의 진입 클래스 |
| `hostApi` | 호스트 인터페이스 버전, 정확히 일치 |
| `runtimeFingerprint` | 공용 라이브러리/ABI/리소스 계약의 SHA-256, 정확히 일치 |
| `minBaseVersion`, `maxBaseVersion` | 지원하는 베이스 APK versionCode 범위, 양 끝 포함 |
| `minSdk`, `maxSdk` | Android API 범위, 최소 26 |
| `minDataSchema`, `maxDataSchema` | 지원하는 데이터 스키마 범위, 양 끝 포함 |
| `payloadSize`, `payloadSha256` | DEX 페이로드의 바이트 수와 SHA-256 |
| `notesSize`, `notesSha256` | 변경 내역의 바이트 수와 SHA-256 |

서명 알고리즘은 Android 26에서도 제공되는 `SHA256withRSA`다. 검증기는 2048~4096비트 RSA 공개키를 고정 목록에서 받는다. 신규 배포 키는 3072비트를 권장하며 APK 키와 구분한다. 아직 배포용 모듈 키를 만들거나 기존 APK 개인키를 사용하지 않았다. 키 ID는 후보 파일에서 읽지만, 허용 여부는 실행기 내부의 고정 공개키 목록으로 결정한다. ZIP에 들어 있는 공개키나 GitHub의 체크섬 파일로 신뢰를 추가하지 않는다. 키 회전·폐기 및 신뢰 루트 갱신은 별도 설계/구현 대상이다.

런타임 지문은 임의 문자열이 아니라 호스트/모듈의 빌드 도구·Compose/Kotlin·공유 ABI·리소스 ID 규약을 같은 방식으로 계산해야 한다. 실제 계산/빌드 연결은 다음 단계다. 첫 전환에서 JNI·코덱·시스템 컴포넌트는 베이스에 남긴다.

## 적용 상태

`ModuleActivationPolicy`는 실행 가능한 파일을 열거나 Android 프로세스를 재시작하지 않는다. 다음 상태와 결정만 반환하는 불변 모델이다.

1. `stage`: 검증한 후보를 보관할 상태를 만들며 승인은 기본 거짓이다. 현재 버전이나 최고 승인 버전 이하의 후보는 받지 않는다.
2. `approve`: 사용자가 확인한 아카이브 해시가 현재 후보와 같을 때만 승인한다. 새 후보의 해시는 이전 승인을 사용할 수 없다.
3. `prepareStartup`: 새 프로세스의 사용자 화면 시작이며 재생·공유·백그라운드 작업이 없을 때만 적용한다. 호환성을 다시 확인한다. 이전 정상 버전을 보존하고 시험 부팅 표시를 먼저 남긴다.
4. `confirmHealthy`: 실제 호스트가 화면과 필수 서비스 초기화 완료를 확인한 뒤 정확한 활성 해시로 호출한다. 단순히 클래스 로딩에 성공했다는 이유로 호출하지 않는다.
5. 시험 부팅 표시가 남은 다음 프로세스는 이전 정상 버전의 호환성과 보안 하한을 확인한 뒤 복구한다. 복구한 뒤에도 최고 승인 버전은 낮추지 않으므로 같은 실패 버전을 자동 반복 적용하지 않는다.

복구 버전이 변경된 DB와 맞지 않거나 폐기된 버전이면 `RecoveryRequired`를 반환한다. 이 경우 호스트는 해당 코드를 실행해서는 안 된다. 원래 데이터를 보존하고, 호환되는 내장 기본 구현/베이스 복구 경로를 제공해야 한다. 현재 모델이 DB를 백업하거나 되돌려 주지는 않는다. 불가역 DB 변경은 첫 기능 패키지 전환의 대상에서 제외한다.

## Android 호스트에 남은 필수 연결

반환된 상태는 **코드를 실행하기 전에** 원자적으로 영속 저장해야 한다. 여러 업데이트/시작 요청을 직렬화하고 한 프로세스의 모듈을 교체하지 않는다. 파일은 앱 전용 `noBackupFilesDir`의 후보/정상 슬롯에 저장하고, 로딩 직전에도 다시 검증한다. API34+ 요구에 맞춰 열린 파일을 먼저 읽기 전용으로 바꾼 뒤 그 descriptor로 쓰는 경로가 필요하다. code cache는 다시 만들 수 있는 최적화 결과에만 사용한다.

현재 구현에는 이 영속 저장소, 내장 기본 모듈, 기존 화면/서비스 경계와 네트워크가 없다. `runtime-host`에 별도 DEX를 로딩하는 **시험 부팅 전용 로더**를 만들었으며, `runtime-probe`의 새 Compose fixture를 실행하는 기기 검사에만 사용한다. 기존 앱의 안정 버전 실행/복구 경로를 대신하지 않는다. 상태 모델 자체도 크래시 내구성이나 사용자 동의 UI를 대신하지 않는다. `approve`를 다운로드 완료 콜백에서 호출하거나 `freshProcess`를 Activity 생성 때마다 참으로 주어서는 안 된다.

동적 네이티브 코드는 호스트의 UID·허용된 권한으로 실행되므로 신뢰할 수 없는 모듈의 격리 환경이 아니다. 검증된 공식 모듈만 로딩하며, 새 권한·시스템 구성요소가 필요하면 베이스 APK를 갱신한다. 실제 Android 로딩/기능·디자인 보존 검사는 현재 JVM 검사와 별도로 수행해야 한다.

## 검사

```sh
./gradlew :runtime-core:test
```

검사는 유효한/변조된 서명과 페이로드·변경 내역, 잘못된 ZIP/JSON, 호환성 범위, 정확한 파일에 묶인 승인, 재생·공유·작업 중 적용 연기, 시험 부팅/복구와 비호환 데이터 보호를 다룬다. 테스트용 페이로드는 실행 코드가 아닌 바이트 fixture이며 실제 Android에서 DEX/Compose 화면을 실행했다는 증거가 아니다. CI는 JUnit XML을 별도 아티팩트로 남긴다.

별도 `NativeModuleLoadingTest`는 실제 DEX를 자산으로 받는다. 시험용 RSA 키는 기기 검사 프로세스의 메모리에서만 생성한다. 설치/승인 전 클래스 초기화 없음, 승인된 정확한 패키지 재검증, 읽기 전용 파일, 외부 클래스 로더에서의 실제 Compose 표시/클릭, 파일 변경·비호환·버전 혼합 거부를 확인한다. 이 자산은 테스트 APK에만 들어가며 앱 APK에는 들어가지 않는다. 기기 매트릭스는 API26/29/30/35/37이다. 실행 결과를 확인하기 전에는 통과했다고 기록하지 않는다. 프로덕션 R8 ABI와 기존 리소스 전달은 별도 검증 대상이다.

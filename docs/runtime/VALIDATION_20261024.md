## 네이티브 검사에 포함한 동작

- 검증/승인만으로 다운로드 클래스가 초기화되지 않으며, 정확한 아카이브를 승인한 뒤 실제 외부 DEX 클래스가 생성된다.
- 별도 빌드한 Compose 화면이 표시되고 버튼 클릭으로 상태가 바뀐다. Kotlin/Compose/API 클래스 복사본은 DEX 전용 probe에 들어 있지 않는다.
- 원문 서명·내용·호환성 재검증, 쓰기 가능한 파일·다른 아카이브·변조 DEX·프로세스 내 버전 혼합 거부.
- 승인/시험 적용을 AtomicFile에 먼저 저장하고, 저장소 재열기·시험 미완료 복구·정상 부팅 확정·원자 쓰기 중단·상태 손상·동시 승인·취소를 검사한다.
- 읽기 권한이 손상된 상태 파일을 첫 설치로 오인하여 초기값으로 되돌리지 않는다.
- **호스트와 같은 앱 ID와 `chromahub.rhythm.app.R` 이름**을 가진 APK 형태의 페이로드에서 새 문자열·벡터 이미지를 읽는다. 호스트의 R 클래스에 없는 필드가 기능 로더에서 정의되며, 실제 설치된 호스트 APK 경로는 바뀌지 않는다.
- 영어/한국어 리소스 컨텍스트를 별도로 만들고, 한국어를 읽은 뒤 원래 영어 컨텍스트가 영향을 받지 않는지 확인한다.

API26/29/37의 실제 PNG에서 외부 DEX의 Compose 화면과 클릭 후 숫자 1을 확인했다. 시험 화면은 기존 음악 앱의 새로운 디자인이 아니다. Google ATD는 화면 출력을 비활성화하므로 API35의 의미/클릭/상태 검사를 픽셀 증거로 사용하지 않는다. API30 결과도 통과 개수로 확인했으며 화면 캡처 증거로 확대하지 않는다.

## 시험 중 수정한 문제

첫 API26 실행은 테스트 전 `logcat -c`가 거부되어 실제 검사가 시작되지 않았다. 로그 초기화만 비필수 진단으로 바꾸고 실제 18개 결과는 계속 엄격히 검사한다.

언어별 리소스의 파일 경로를 분리하는 초기 hard-link 실험은 Android 앱 샌드박스가 `EACCES`로 거부했다. 이 실패를 통과로 세지 않았다. 공개 파일 API로 읽기 전용 복사본을 만든 뒤 크기·해시를 다시 검사하도록 바꿨다. SELinux나 앱 권한을 완화하지 않았다. 큰 실제 기능 패키지에는 리소스 전용 파일/캐시 예산·정리가 추가로 필요하다.

## 빌드 리소스 ID 준비

`scripts/export_runtime_resource_ids.py`는 별도로 검증한 APK 체크섬을 확인한 뒤 AAPT2 `--stable-ids` 입력을 만든다. 공개 1326 debug APK에서 자동 생성 `$` 이름을 포함한 **13,441개** 리소스를 빠짐없이 내보냈다. 새 문자열을 중간 이름으로 추가하는 실제 AAPT2 링크에서 고정 목록이 없으면 기존 ID가 바뀌고, 고정 목록을 주면 유지되는 것을 확인했다. 공개 APK의 전체 목록도 AAPT2가 받아들이며 기존 `string/app_name` ID `0x7f12007f`가 유지됐다. 이 도구는 아직 실제 호스트/기능 빌드에 연결하지 않았다.

## 현재 완료 범위와 남은 작업

기존 `app/src/main` 소스·manifest·리소스는 변경하지 않았다. 새 코드/자산은 instrumentation 경로에만 연결되어 일반 앱 APK에 probe 페이로드가 포함되지 않는다. 따라서 기존 기능을 제거한 변경은 없지만, **음악 앱 전체를 모듈로 옮긴 뒤의 동등성은 아직 검사한 것이 아니다.**

기본 음악 패키지 분리, 실제 Activity/미디어 서비스/위젯/Worker 위임, 기존 데이터의 베이스 전환, 실제 런타임 지문/리소스 ID 빌드 연결, minify된 독립 조합, 다운로드·사용자 동의 UI·실제 배포 키/게시를 이어서 구현해야 한다. [전체 이전 경계](MIGRATION_PLAN.md)의 완료 조건을 통과하기 전에는 완성판으로 배포하지 않는다.

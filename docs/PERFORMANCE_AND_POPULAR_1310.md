# 인기 리스트와 오래 쌓이는 청취 기록

5.5.499.1310에서 인기 음악 탐색을 일반 탐색 탭으로 옮기고, 기록이 많아질수록 앱이 무거워지는 경로를 줄였습니다. 원본 청취 기록을 삭제해서 가볍게 만드는 방식은 사용하지 않습니다.

## 인기 리스트

하단 탐색 막대의 **인기**에서 곡·앨범·아티스트 목록을 봅니다. 기존 미니 플레이어와 검색, 라이브러리 탐색을 그대로 사용할 수 있습니다. 좁은 탐색 막대에서는 라이브러리를 **보관함**으로 표시해 큰 글꼴에서도 이름이 잘리지 않게 했습니다. 앨범이나 아티스트를 누르면 해당 인기곡으로 좁혀집니다.

곡 점수는 각 사이트의 1~100위에 `(101 − 순위) / 100`을 적용한 뒤 **멜론 50%, 벅스 30%, 지니 20%**를 더합니다. 두 사이트에 함께 오르면 0.10, 세 사이트에 오르면 0.20을 추가합니다. 한 사이트 안의 중복 곡은 가장 높은 순위 한 번만 계산합니다. 제목·버전·아티스트 표기가 다른 항목은 오매칭을 피하기 위해 별개로 유지합니다.

앨범·아티스트 순위는 이 인기곡 점수를 모은 결과입니다. 별도의 공식 앨범·아티스트 차트라는 뜻은 아니며 화면에서도 이를 알립니다. 순위 기준 버튼에서 계산 방식을 확인할 수 있습니다.

목록은 먼저 기기에 저장된 내용을 보여 줍니다. 자동 갱신은 한 시간 간격이며, 직접 새로고침해도 같은 사이트에는 최소 5분 간격을 둡니다. 세 사이트를 순서대로 요청하고 기존 요청 간격·실패 대기를 사용합니다. 일부 사이트가 실패하면 가능한 저장 목록을 유지하고 그 상태를 표시합니다. 다운로드 버튼은 기존의 출처 선택·백그라운드 다운로드 흐름으로 연결됩니다.

**음악 정보·가사 수집의 기본 우선순위는 계속 벅스 → 멜론 → 지니입니다.** 인기 순위의 가중치와 구별됩니다.

## 수집과 분석의 부하

- 실제 재생 중에만 30초 간격으로 누적 청취 구간을 체크포인트로 저장합니다. 일시정지 중에는 주기 기록을 만들지 않습니다. 곡 전환·정지 등 구간이 끝나는 동작은 별도로 기록합니다.
- 크로스페이드·정규화 등의 자동 음량 변화는 사용자 행동 이벤트로 기록하지 않습니다. 사용자가 앱 음량을 조절하면 1초간 모아 최종 변화를 기록합니다.
- 설정·오디오 출력·화면 밝기 등의 상황 값은 IO 스레드에서 약 90초 간격으로 확인합니다. 절전 모드·낮은 배터리·발열 상태이면 180초로 늘립니다.
- 이동 감지는 화면이 보이고 재생 중일 때 120초마다 6초의 짧은 센서 구간을 사용합니다. 부담이 있으면 300초로 늘립니다. 원시 센서 궤적은 보관하지 않습니다.
- 선택적으로 켜는 주변 소음 수준 측정은 화면이 보이고 재생 중일 때 180초마다 1초만 실행합니다. 마이크 원음 파일은 저장하지 않습니다. 위치 권한과 기록 선택도 계속 존중합니다.
- 측정 사이에는 유효 기간 안의 최근 상황 값과 **측정 시점·경과 시간·이전 값 사용 여부**를 함께 기록합니다. 측정하지 않은 정밀 위치·이동 경로·소음이나 실제로 듣지 않은 시간은 만들어 넣지 않습니다.
- 추천 재학습·상세 분석·자동 백업은 충전·유휴·배터리 및 저장 공간 조건을 기다립니다. 분석 전용 저우선순위 스레드 하나에서 짧게 처리하고 쉬며, 발열이나 전원 상태가 바뀌면 중단·재개합니다. 수동 백업은 계속 사용할 수 있습니다.

이벤트 쓰기는 재생 UI와 분리합니다. 저장이 밀리면 같은 누적 체크포인트를 합치고, 대기열에 메모리 상한을 둡니다. 장시간 저장 실패로 일부 대기 이벤트를 보관할 수 없게 되면 누락 개수를 별도 기록하며 이를 청취 시간으로 추정하지 않습니다. 기록은 저널에 먼저 내구성 있게 저장하고 데이터베이스에 반영합니다. 비정상 종료 시 마지막 체크포인트 뒤의 청취는 복구되지 않을 수 있습니다.

## 한 번 충분히 들었던 곡과 반복 재생

서로 겹치지 않는 실제 청취 구간이 곡 길이의 **90% 이상**인 기록을 충분히 들었다는 근거로 보관합니다. 탐색바를 끝으로 이동한 것만으로 완청 처리하지 않습니다.

그 근거가 생긴 뒤 같은 곡을 짧게 듣고 이동한 경우, 자동 부정 학습에서 제외합니다. 바로 이어서 같은 곡을 반복해 듣는 경우에는 긍정 신호로 해석합니다. 실제 청취 비율·날짜·간격은 원본 그대로 남습니다. 사용자가 직접 누른 싫어요나 숨김은 계속 반영합니다.

이전 버전의 기록도 삭제하지 않고 충전·유휴 상태에서 순서대로 다시 해석합니다. 과거 기록의 색인이 아직 준비되지 않은 곡은 부정 학습을 보류합니다. 이전 정책으로 만들어진 학습 가중치는 새 정책으로 재구축하며 직접 평가한 기록은 유지합니다.

## 통계를 다시 열 때

통계는 작은 결과 파일을 앱 내부 저장소에 보관하여 앱을 다시 실행해도 먼저 표시할 수 있습니다. 이후 현재 기록과 라이브러리를 확인하고 갱신합니다. 화면에 보이는 기간만 계산하고, 이전 기간과의 비교가 준비될 때까지 현재 통계 표시를 기다리게 하지 않습니다.

전체 기록을 풍부한 JSON 객체 목록으로 한꺼번에 읽지 않습니다. 필요한 열만 데이터베이스에서 순서대로 읽고 청취 구간을 합산합니다. 최근 재생·반복 재생·오래 안 들은 곡과 홈의 오늘 청취 시간도 각각 색인된 조회를 사용합니다. 홈 화면은 재생 위치가 움직일 때마다 전체 통계를 다시 계산하지 않습니다.

캐시는 기록 세대·변경 번호·라이브러리 메타데이터·날짜·언어·시간대·아티스트 분리 설정을 확인합니다. 기록 삭제·복원과 동시에 끝난 과거 계산이 새 캐시로 되살아나는 것을 막습니다. 기본 통계는 전체 해당 기간을 집계합니다. 비용이 큰 상세 상황 분석의 예시는 최근 구간으로 제한하며 화면에 **표본 수와 계산 시점**을 표시합니다. 원본 전체 기록과 장기 선호 색인은 유지합니다.

## 기존 데이터와 백업

청취 데이터베이스에 필요한 열과 색인을 추가하며 기존 테이블을 지우지 않습니다. 이전 데이터베이스의 JSON 열은 필요할 때 최소 정보만 읽고, 전체 보강 작업은 충전 중 나누어 수행합니다.

백업 파일마다 전체 설정 XML을 다시 쓰던 복사 확인 기록을 별도 SQLite 색인으로 옮깁니다. 기존 확인 값을 먼저 새 색인에 저장한 다음 해당 확인 값만 설정에서 제거하며, 백업 폴더나 사용자 옵션은 유지합니다. 파일 목록은 한꺼번에 메모리에 담지 않고 순회하고, 큰 파일도 작은 버퍼로 나누어 복사합니다. 저널의 일관된 복사 범위를 정한 뒤에는 오래 걸리는 파일 복사 동안 청취 기록 쓰기를 막지 않습니다.

이미지 미리 읽기는 주변 항목에만 적용하고, 인덱스 생성은 UI 스레드 밖에서 수행합니다. 메모리 부담이 있을 때는 추측해서 읽는 이미지의 개수와 크기를 줄입니다. 실제 보고 있는 이미지는 정상 화질로 표시합니다.

검증 결과와 실제 앱 화면은 [1310 검증 기록](validation/v1310/REPORT.md)에 정리합니다.

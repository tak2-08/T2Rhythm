# 상황 추천과 뮤직비디오

T2Rhythm 5.5.498.1305에서 추천·청취 맥락·영상·업데이트를 기존 보관함과 통합했습니다.

## 추천 데이터와 학습

기존 영구 청취 저널은 유지합니다. 시간대·요일·장르 전환·재청취 간격·완주율·빠른 스킵·최근 취향에 장소와 오디오 출력 맥락을 추가했습니다. 선호 아티스트/장르, 즐겨찾기, 추가 시점, 미청취 곡과 전체 PCM 분석의 음향 유사도도 사용합니다. 최신 상황 신호는 최근 90일의 최대 20,000개 구간과 20,000개 행동에서 계산하며, 원본 기록이나 전체 통계는 이 한도 때문에 삭제·축소하지 않습니다.

추천은 다음 순서로 계산합니다.

1. 평생 선호와 최근 상황 신호를 구성합니다. 표본이 적은 신호는 완화하고 최근 취향에는 시간 감쇠를 적용합니다.
2. 13개 특징을 고정된 스키마로 만들고 기본 규칙과 기기 내부 온라인 로지스틱 학습 점수를 합칩니다. 학습 표본이 적으면 학습 점수 영향도도 낮춥니다.
3. 현재 곡과 사용자가 명시적으로 덜 추천한 곡을 제외합니다. 아티스트·장르 반복을 줄이고, 기본 15%의 발견 순서에는 미청취 곡을 우선합니다.
4. 홈에서 제시한 목록·순서·특징·예측을 기록합니다. 이는 UI에 목록을 구성한 기록이며 실제 화면 응시를 측정하는 지표는 아닙니다.
5. 개인 믹스에서 선택한 첫 곡의 완주/80% 이상 청취 또는 빠른 스킵과 명시적 피드백으로 가중치를 갱신합니다. 뒤따르는 자동 재생을 모두 독립적인 추천 선택으로 간주하지 않습니다.
6. 해당 반응을 학습하기 **전** 예측의 Brier 오차를 기록합니다. 고정 확률 0.5의 기준 오차와 함께 표시합니다. 표본은 추천 선택·피드백에 치우칠 수 있으며 더 많은 데이터가 언제나 더 좋은 추천을 보장하지 않습니다.

플레이어의 추천 조정 버튼은 **더 추천 / 덜 추천 / 이 곡 선호 초기화**를 제공합니다. 초기화는 해당 곡의 명시적 선호를 지우며 과거 학습 이벤트를 삭제하는 기능은 아닙니다. 기본 규칙의 `context`, `learning`, `exploration` 가중치는 기존 스키마 1 JSON 가져오기/선택적 규칙 업데이트에서도 지정할 수 있습니다. 실행 코드는 내려받지 않습니다.

`music_metadata/recommendations/*.jsonl`은 영구 원본입니다. 중복 이벤트 ID는 다시 학습하지 않으며 모델은 원본에서 재구성합니다. 추천 제시와 반응의 특징·예측·알고리즘 이름을 남기므로 추후 다른 알고리즘으로 같은 기록을 다시 분석할 수 있습니다. 최근 선택 정보도 프로세스 재시작 후 복구합니다. 월별 기록에는 출력별 청취 시간과 장소 그룹 수를 표시합니다.

## 위치와 오디오 출력

설정 → 내 음악 보관함 → 청취 경험에서 위치 기록을 켭니다. 기본은 꺼짐이며, 대략적 위치와 **정밀 위치를 별도로 선택**합니다. Android 권한을 거절해도 음악과 추천은 동작합니다.

새 위치는 앱이 보이는 동안만 요청합니다. 백그라운드 위치 권한을 요청하지 않으며 앱이 보이지 않을 때 계속 위치를 추적하는 기능은 아닙니다. 15분보다 오래되거나 정확도가 너무 낮은 위치는 사용하지 않습니다. 대략적 모드는 좌표를 약 1km 격자로 묶습니다. 정밀 모드에는 허용된 좌표·정확도·고도·속도·방향·제공처를 남기되, 제공되지 않은 값은 만들지 않습니다. 추천의 장소 그룹은 정밀 모드에서도 격자를 사용합니다. 위치가 없을 때에는 직접 입력한 현재 장소 이름을 이용할 수 있습니다.

출력은 기기 스피커·유선·블루투스·USB·캐스트를 구분합니다. 연결된 기기의 제품 이름·샘플레이트·채널·인코딩 목록, 시스템 음악 볼륨과 최대 볼륨, 충전 여부·배터리 잔량도 기록합니다. 오디오 능력 목록은 연결 기기의 지원 능력이며 실제 디코더가 사용하는 샘플레이트를 뜻하지 않습니다. 추천에서는 출력 종류와 사용 가능한 연결 기기 이름을 함께 묶어 서로 다른 이어폰의 선호를 구분합니다. 실제 활성 기기를 확정할 수 없는 경로는 이 구분도 추정값입니다. 현재 출력 경로는 Android 시스템 경로와 오디오 상태로 **추정**하고 연결 기기 목록과 구분해 저장합니다. 블루투스 MAC 주소는 수집하지 않습니다. 맥락이 바뀌면 청취 구간을 나눕니다.

위치·기기 정보와 청취 기록은 앱이 서버로 업로드하지 않습니다. 사용자가 지정한 영구 백업 폴더에는 이 정보가 포함됩니다.

## 영상 보기

Material/Expressive 플레이어의 아트워크 영역에서 비디오 아이콘을 누릅니다. 기본은 **무음 영상 + 기존 음원 유지**입니다. 가사를 보거나 화면을 떠나면 별도 영상 플레이어를 계속 실행하지 않습니다. 영상이 활성화된 동안 기존 Canvas 애니메이션 재생을 멈춥니다.

- **YouTube 후보 찾기**: 곡의 아티스트와 제목으로 후보를 검색하고 사용자가 선택합니다. 자동으로 정답이라고 단정해 연결하지 않습니다. 검색 실패 시 YouTube 검색과 직접 링크 입력을 제공합니다. 외부 사이트의 응답·차단·임베드 허용 여부에 따라 이용 가능성이 달라집니다.
- **링크 추가**: YouTube/YouTube Music/youtu.be 링크의 검증된 영상 ID만 저장합니다. 공식 YouTube iframe 플레이어로 재생하고 광고·제어 UI를 덮거나 영상을 추출·다운로드하지 않습니다. 재생 제한이 있는 영상은 영상 관리의 YouTube에서 열기를 사용합니다.
- **파일 추가**: 문서 선택기로 영상 파일을 골라 앱 보관함에 복사합니다. 지원되는 비디오 트랙만 리먹싱해 오디오 중복을 제거합니다. VP8/VP9는 실제 WebM, 다른 지원 코덱은 MP4입니다. 확장자만 바꾸거나 H.264를 WebM이라고 저장하지 않습니다. 짧은 WebM 등 플랫폼 리먹싱 결과가 더 커지는 경우, 형식이 확인된 더 작은 호환 원본을 보관합니다. 이 경우 원본에 오디오가 남을 수 있지만 재생은 무음입니다. 디코딩/재인코딩으로 화질을 낮추는 기능은 아니므로 원본 대비 항상 크게 작아지는 것은 아닙니다.
- 영상 트랙·코덱 설정·시간 기준의 SHA256으로 중복 영상을 공유합니다. 직접 추가는 최대 1GB이며 공간이 부족하거나 암호화/지원하지 않는 트랙은 적용하지 않습니다.
- 음원의 진행 위치를 참고해 영상을 맞추고, 관리 창의 ±5초 버튼으로 인트로 차이를 보정합니다. 네트워크 버퍼링을 포함한 프레임 단위 동기화를 보장하지는 않습니다.

영상 연결을 해제해도 공유 영상 파일은 복구를 위해 남겨둡니다. 해제 상태는 기록으로 저장해 백업에도 반영합니다. 연결 JSON과 영상 파일은 `music_metadata/videos/`에 일반 파일로 보관합니다.

## 이미지

수집한 곡·앨범·아티스트 아트와 직접 지정한 아트는 공통 WebP 저장 경로를 사용합니다. 일반 저장은 최대 1600px, 품질 86이며 투명도를 지원하고 동일한 인코딩 결과는 SHA256으로 공유합니다. 원본 아트워크 모드의 추출 캐시는 WebP 품질 100을 사용합니다(지원 Android 버전에서는 무손실 인코딩). 초대형/변환 실패 아트와 기존 파일에는 호환 경로를 유지합니다.

음원 원본의 정확한 롤백을 위해 기존 이미지 바이트도 별도 보관합니다. MP4 커버 및 외부 플레이어 호환성을 위해 **음원 내장** 시에는 필요한 JPEG/PNG 바이트로 변환하며, 앱에 저장하는 표시 이미지는 WebP입니다. 기존 JPEG/PNG 파일을 강제로 삭제하지 않습니다.

## 업데이트

앱 화면과 백그라운드 확인 모두 `tak2-08/T2Rhythm`의 **태그**를 비교합니다. 한국어 릴리스 제목을 버전 숫자로 읽지 않습니다. 설치한 일반/Debug 패키지와 지원 ABI에 맞춰 실제 `T2Rhythm-버전.apk` 자산을 선택합니다.

다운로드는 릴리스의 SHA256, 파일 크기, 재개 바이트 범위, APK 패키지·버전·서명을 검증합니다. 크기가 달라도 무시하고 설치하는 경로는 제거했습니다. 검증 정보가 없는 배포물은 앱 내 설치 대신 브라우저 안내를 제공합니다. 검증한 파일은 설치 직전과 프로세스 재시작 후에도 다시 확인합니다. 설치창을 취소했거나 알 수 없는 앱 설치 권한 설정을 거쳐 돌아와도 파일을 유지해 재시도할 수 있습니다. 구형 Android에서 서명 정보를 읽는 호환 경로도 검증합니다. 설치창 실행을 설치 성공이라고 취급하지 않습니다. 다음 실행에서 설치된 버전이 다운로드한 버전에 도달했을 때 완료 상태를 정리하며 APK 자체를 즉시 삭제하지 않습니다.

Android의 설치 승인과 Play Protect 판단은 앱이 우회하지 않습니다. 네이티브 기능 변경은 APK 업데이트가 필요하며 기존 지원 JSON 규칙의 데이터 변경과 구분합니다.

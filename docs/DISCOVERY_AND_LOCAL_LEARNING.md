# 인기 음악, 다운로드와 온디바이스 학습

5.5.498.1309부터 검색 화면의 **인기 음악**과 **정보 제안**, 설정의 저장 공간 항목에 있는 **백그라운드 다운로드**를 이용할 수 있습니다.

## 인기 음악에서 내 보관함까지

벅스 → 멜론 → 지니 순서로 사이트를 선택합니다. 각 사이트의 공개 음악 차트를 읽으며 앨범·아티스트 탭은 그 차트의 등장 횟수와 최고 곡 순위를 기준으로 묶습니다. 별도의 공식 앨범·아티스트 차트 순위로 표시하지 않습니다. 캐시는 한 시간 사용하고, 수동 새로고침도 5분 이내에는 재요청하지 않습니다. 차트 요청은 기존 수집기의 사이트별 간격·차단 대기 정책을 사용합니다. 접근 실패 시 이전 자료와 갱신 시각을 표시합니다.

음악을 선택하면 YouTube 또는 SoundCloud에서 검색하거나 직접 HTTPS 오디오 주소를 입력합니다. 제목·업로더·길이와 원본 페이지를 확인하고 저장할 소스를 직접 선택하세요. 같은 제목의 라이브·커버·리믹스는 원곡과 다를 수 있습니다. 저장한 음원은 `Music/T2Rhythm`에 들어가 기존 라이브러리와 태그 편집·가사·음악 정보 기능을 이용합니다. 전체 UUID가 포함된 파일명으로 작업 재개 시 중복 파일 생성을 방지합니다.

NewPipeExtractor(GPL-3.0-or-later)의 YouTube·SoundCloud 추출과 검색, OkHttp(Apache-2.0)의 HTTPS 전송을 사용합니다. 오디오 전용 스트림을 선택하며 대략 128kbps에 가까운 형식을 우선합니다. SoundCloud의 공개 VOD HLS도 지원합니다. 암호화되지 않은 AAC/fMP4 조각은 순차적으로 이어받아 Android MediaMuxer로 재포장하고, MP3 조각은 연결합니다. 실제 곡 길이와 다른 미리 듣기, 암호화·실시간·지원하지 않는 재생목록은 저장하지 않습니다. 소스의 실제 형식과 비트레이트에 따라 크기가 달라지고, 추가 손실 압축을 하지 않습니다. 영상은 기존의 최대 720p·30fps 무음 WebM/MP4 정책을 유지합니다. 제공처의 차단·로그인 요구·스트림 형식 변경 등에 따라 다운로드할 수 없는 항목이 있습니다. 사이트의 유료 음원 접근 권한을 변경하는 기능은 없습니다.

## 화면을 떠나도 유지되는 다운로드

작업과 진행량은 영구 작업 인덱스와 Android WorkManager에 저장합니다. 곡·앨범·재생목록 화면을 옮겨도 계속되며, 설정에서 진행량·저장 용량·대기·실패 내역을 확인하고 취소·재시도합니다. 기존 버전에서 대기하던 영상 작업도 복구합니다. 기본은 Wi-Fi이며, 오디오 저장 시 모바일 데이터 사용을 직접 선택할 수 있습니다.

네트워크 다운로드는 최대 두 개, 저메모리·절전·발열·공간 부족 상태에서는 새 작업을 한 개씩 허용합니다. 추출과 파일 설치는 각각 직렬화합니다. 강한 ETag와 정확한 Content-Range를 검증할 수 있을 때만 부분 파일을 이어받습니다. 완료된 임시 파일은 재사용하고, 라이브러리에는 내용 검증을 마친 파일만 공개합니다. 취소 시 임시 파일을 정리하고 영구 저장을 마친 파일은 보존합니다. 운영체제의 백그라운드 제한으로 일시 대기할 수 있습니다.

## 상황이 결합되는 추천

이동 수단 추정·낮과 밤을 단독 점수로만 사용하지 않고 이동×낮밤, 시간×출력 기기, 장소×날씨, 출력×음량, 이동×날씨 조합을 누적합니다. 조합별 장르 선호를 실제 청취 비율과 음향 유사도에 결합해 학습합니다. 드문 조합의 영향은 완화합니다. 기존 기록과 추천 피드백을 보존하며, 파생 인덱스만 충전 중 재구축합니다.

추천 카드에서 바꿔 달라고 누르면 새 믹스 세대가 생성됩니다. 각 세대는 곡 목록·평가 식별자가 독립적입니다. 방치한 추천은 기본 6시간 후 새 추천 대상으로 삼고, 최근 30분 동안 재생·열기·평가한 카드는 보호합니다. 주기는 1~48시간으로 선택합니다. 백그라운드 확인은 시간 단위로 실행하므로 갱신 시각이 정확히 일치하지 않을 수 있습니다. 재생 중인 큐를 자동 교체하지 않고 이전 믹스는 서랍에 남깁니다.

검색 추천어는 현재 개인 추천에 해당하는 실제 라이브러리의 가수·장르·제목에서 고릅니다.

## 장르와 가사 제안

**가벼운 분석이 기본**입니다. 충전·유휴·배터리·저장 공간 조건을 모두 충족할 때 기존 저부하 분석 스레드에서 나눠 처리합니다. 알려진 장르 태그와 로컬 음향 특징으로 학습하고, 미등록 곡에 충분한 근접 사례가 있을 때만 장르를 제안합니다. 추정 장르는 추천의 보조 자료로 구분해 사용하며, 사용자가 수락하기 전에는 원래 태그를 바꾸거나 정답 학습 자료로 쓰지 않습니다. 거절한 제안은 이후 판단에 반영합니다.

가사 타이밍은 세 가지 방식을 선택합니다.

- **가벼운 분석:** 같은 PCM 지문·같은 가사의 검증된 타이밍을 참조하거나, 다른 동기 가사의 도입부·끝부분·문장 속도와 대상 음원의 에너지 골을 이용해 예상합니다. 예상안은 낮은 참고 점수로 표시하며 실제 가창 인식 결과와 구별합니다.
- **정밀 분석:** 선택적으로 받은 한국어 Vosk 모델로 음원 파일을 짧게 디코딩하고, 인식된 단어와 가사를 순서대로 연결합니다. 모델 또는 충분한 인식 기준점이 없으면 가벼운 예상안으로 폴백합니다.
- **혼합 분석:** 두 결과를 비교해 근거가 더 강한 제안을 사용합니다.

[Vosk Android](https://github.com/alphacep/vosk-api)(Apache-2.0) 0.3.75와 [공식 한국어 소형 모델](https://alphacephei.com/vosk/models)(Apache-2.0) `vosk-model-small-ko-0.22`를 사용합니다. 모델은 별도 동의 동작인 설치 버튼으로만 받고, Wi-Fi·충전 조건에서 설치합니다. 다운로드 86,914,329바이트, 설치 후 약 265MB이며 SHA-256 `eea36124087fed26c59996a4761519458e3bd185e8ea9d9865ad8760c4a1d989`를 검증합니다. 모델은 다시 받을 수 있는 전용 공간에 두고 개인 백업에서는 제외합니다. JNA는 Apache-2.0/LGPL-2.1-or-later 이중 라이선스입니다.

정밀 분석은 마이크를 사용하지 않습니다. 중간 인식 결과와 분석 위치를 영구 체크포인트에 저장해 작업을 이어가며, 단어와 원문이 충분히 맞지 않으면 제안하지 않습니다. 일반 음성 모델이므로 노래·반주·랩·다국어 가사의 정확도를 보장하지 않습니다. 가벼운 방식 역시 타이밍의 정답을 생성하는 모델은 아닙니다.

**정보 제안**에서 변경 전·후 시간, 근거와 참고 점수를 보고 곡을 재생해 해당 줄로 이동할 수 있습니다. 수락·거절을 직접 선택하고, 수락한 제안은 이력에서 되돌릴 수 있습니다. 다른 편집이 이미 이루어졌으면 오래된 제안을 적용하지 않습니다. 가사를 수락하면 기존 가사 파일·음원 내장 저장 경로와 Android 파일 수정 권한 흐름을 사용합니다. 단어 단위 가사를 줄 단위 제안으로 낮춰 덮어쓰지 않습니다. 원본 가사·장르와 결정 이력은 백업 가능한 개별 파일로 남습니다.

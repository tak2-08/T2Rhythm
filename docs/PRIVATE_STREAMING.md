# T2Rhythm Streaming

설정의 **T2Rhythm Streaming**을 이용하면 서브폰에 보관한 음악을 메인폰이나 초대한 친구의 T2Rhythm에서 들을 수 있습니다. APK 버전 5.5.499.1323부터 지원합니다. 별도 Debian 환경이나 음악 중계 서버를 설치할 필요가 없습니다.

## 같은 Wi-Fi에서 시작하기

1. 음악이 있는 폰에서 기기 라이브러리를 불러옵니다. 설정 → T2Rhythm Streaming → **폰에서 실행**으로 갑니다.
2. 기기의 모든 음악 또는 공유할 플레이리스트를 고른 뒤 **음악 서버 시작**을 누릅니다. 서버는 스캔된 로컬 음악만 제공합니다. 온라인 스트리밍 URL을 다시 공유하지 않습니다.
3. **기기 초대**에서 상대 폰이 연결할 수 있는 주소를 고르고 초대를 복사하거나 공유합니다. 초대는 10분 동안, 한 번만 연결을 요청할 수 있습니다.
4. 상대 폰의 **연결하기**에서 초대를 붙여 넣고 기기 이름을 정한 뒤 연결을 요청합니다.
5. 두 폰의 여섯 자리 확인 숫자가 같은지 확인합니다. 서버 폰에서 승인하면 음악 목록을 검색하고 재생할 수 있습니다.

공유기에서 기기 간 통신을 막는 게스트 Wi-Fi나 AP 격리가 설정되어 있으면 연결되지 않을 수 있습니다. Android 17 이상에서는 로컬 네트워크 권한을 허용해야 합니다.

## 밖에서 연결하기

T2Rhythm은 두 폰 사이에서 도달 가능한 네트워크를 사용합니다. 가장 간편한 방법은 두 폰을 사용자가 관리하는 같은 개인 VPN에 연결하는 것입니다. WireGuard, Tailscale 등에서 서버 폰의 VPN 주소를 확인한 다음 그 주소와 포트 **8898**을 초대에 입력합니다.

이미 연결한 서버라면 **주소 변경**에서 새 VPN 주소를 입력하세요. 예: `https://100.90.80.70:8898`. 주소가 달라져도 기존 서버 인증서가 일치하는지 확인한 뒤 저장합니다. 서버의 VPN 주소나 개인 DNS 이름을 유지하면 매번 초대할 필요가 없습니다.

사용자가 직접 설정한 라우터/IPv6 경로도 이용할 수 있습니다. 외부 포트와 내부 8898 포트가 연결되어 있어야 합니다. 앱은 공유기 포트를 자동으로 열거나 공인 IP를 조회하지 않습니다. 통신사의 CGNAT, 방화벽, VPN 접근 정책에 따라 직접 연결은 불가능할 수 있습니다. T2Rhythm 자체에는 중앙 서버나 우회 중계가 없으며 VPN 서비스의 운영 방식은 각 서비스에 따릅니다.

## 음악·캐시·기기 관리

- 곡·아티스트·앨범·장르 검색은 서버의 현재 라이브러리를 대상으로 합니다. 목록은 100곡씩 불러오며 재생 버튼에는 현재 표시한 곡 수가 표시됩니다. 한 목록에 최대 2,000곡을 유지하고, 더 많은 곡은 서버 검색과 장르 필터로 찾습니다.
- 공유받은 음악의 실제 재생은 평소 청취 기록과 통계에 포함됩니다. 연결이 저장된 서버의 곡은 청취 보고서에서도 다시 재생하거나 플레이리스트로 담을 수 있습니다.
- 음악 정보가 바뀌면 서버의 Room 변경을 반영하고 목록 버전을 바꿉니다. 클라이언트의 **라이브러리 새로고침**으로 즉시 반영하며, 화면을 보고 있는 동안에는 주기적으로 변경도 확인합니다. 다음 페이지를 읽는 도중 버전이 바뀌면 목록을 처음부터 새로 가져와 서로 다른 버전이 섞이지 않게 합니다.
- 음원은 전체 복사 없이 필요한 바이트 구간을 전송합니다. 메인 플레이어와 사전 로딩 모두 개인 음악 서버의 인증된 경로를 사용하며 일반 음원 디스크 캐시를 거치지 않습니다. 앨범 표지의 작은 미리보기는 앱의 이미지 캐시를 사용할 수 있습니다.
- 서버 폰의 **접근 취소**는 해당 기기의 새 요청을 차단하고 진행 중인 음원 전송을 끊습니다. 재생 기기에 이미 전달되어 메모리에 버퍼된 부분까지 회수할 수는 없습니다.
- 연결한 폰의 **연결 해제**는 로컬 인증 정보를 지우고 현재 재생을 일시 정지합니다. 서버에도 연결 해제를 요청하며, 서버가 꺼져 있다면 서버 폰에서 별도로 접근을 취소할 수 있습니다.
- 공유할 범위는 서버를 중지한 뒤 다시 고릅니다. 플레이리스트를 선택했을 때는 시작 당시 선택한 로컬 곡을 공유합니다. 이후 플레이리스트에 곡을 더했다면 서버를 중지하고 다시 선택해 실행하세요.
- 연결 승인 정보는 서버 재시작 후에도 유지됩니다. 초대와 아직 승인하지 않은 요청은 서버를 중지하면 폐기합니다. 앱 삭제/데이터 초기화 후에는 다시 연결해야 합니다.

## 전원과 실행

서버를 실행하면 지속 알림이 표시되고 폰을 깨워 연결을 유지합니다. 알림의 **서버 중지**나 앱의 중지 버튼으로 언제든 끝낼 수 있습니다. 서브폰은 충전기에 연결해 두는 것이 좋습니다. 충전하지 않고 배터리가 15% 아래로 내려가면 서버를 중지합니다.

Android와 제조사의 절전 정책, 네트워크 전환, VPN 종료, 앱 강제 종료로 연결이 끊길 수 있습니다. 폰을 다시 켜거나 앱을 강제 종료한 뒤 서버를 자동으로 공개하지 않습니다. 필요할 때 앱을 열고 서버를 다시 실행하세요. 원본 형식 그대로 전송하므로 대용량 무손실 음원은 그에 맞는 네트워크 속도와 데이터가 필요합니다.

## 보안 경계

음악 목록·표지·음원에는 승인된 기기 인증이 필요합니다. 브라우저에서 열 수 있는 공개 음악 페이지, 업로드, 파일 경로 접근, 검색 엔진용 목록을 제공하지 않습니다. 앱 내부의 서버 개인 키는 Android Keystore에서 내보낼 수 없으며, 클라이언트 연결 토큰은 Keystore 키로 암호화해 시스템/앱 백업에서 제외한 영역에 보관합니다. 서버는 토큰 원문 대신 해시를 저장합니다.

초대는 비밀이며 믿을 수 있는 경로로 전달해야 합니다. 인증은 승인한 기기가 음악을 요청할 수 있게 하는 방식입니다. 기기가 탈취되거나 승인받은 사용자가 음악을 별도로 녹음·복사하는 것, 특정 기관의 접근을 모든 상황에서 막는 것을 보장하는 기능은 아닙니다.

개발 참고: [Android 연결 기기 foreground service](https://developer.android.com/develop/background-work/services/fgs/service-types#connected-device), [로컬 네트워크 권한](https://developer.android.com/privacy-and-security/local-network-permission), [Tailscale 기기 연결](https://tailscale.com/docs/how-to/connect-to-devices). 임베디드 HTTP 전송에는 BSD-3-Clause 라이선스의 [NanoHTTPD](https://github.com/NanoHttpd/nanohttpd)를 사용합니다.

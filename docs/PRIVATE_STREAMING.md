# T2Rhythm Streaming

설정의 **T2Rhythm Streaming**을 이용하면 서브폰에 보관한 음악을 메인폰이나 초대한 친구의 T2Rhythm에서 들을 수 있습니다. APK 버전 5.5.499.1323부터 지원합니다. 별도 Debian 환경이나 음악 중계 서버를 설치할 필요가 없습니다.

## 같은 Wi-Fi에서 시작하기

1. 음악이 있는 폰에서 기기 라이브러리를 불러옵니다. 설정 → T2Rhythm Streaming → **폰에서 실행**으로 갑니다.
2. 기기의 모든 음악 또는 공유할 플레이리스트를 고른 뒤 **음악 서버 시작**을 누릅니다. 서버는 스캔된 로컬 음악만 제공합니다. 온라인 스트리밍 URL을 다시 공유하지 않습니다.
3. **기기 초대**에서 상대 폰이 연결할 수 있는 주소를 고르고 초대를 복사하거나 공유합니다. 초대는 10분 동안, 한 번만 연결을 요청할 수 있습니다.
4. 상대 폰의 **연결하기**에서 초대를 붙여 넣고 기기 이름을 정한 뒤 연결을 요청합니다.
5. 두 폰의 확인 코드가 같은지 확인합니다. 서버 폰에서 승인하면 음악 목록을 검색하고 재생할 수 있습니다.

공유기에서 기기 간 통신을 막는 게스트 Wi-Fi나 AP 격리가 설정되어 있으면 연결되지 않을 수 있습니다. Android 17 이상에서는 로컬 네트워크 권한을 허용해야 합니다.

## QR로 초대하기

**기기 초대**에서 상대 폰이 도달할 수 있는 Wi-Fi/VPN 주소로 초대를 만들면 QR이 함께 표시됩니다. 상대 폰에서 **연결하기 → 초대 QR 스캔**을 눌러 카메라로 읽으세요. 별도 QR 앱이나 Google Play 서비스 없이 앱 안에서 읽으며, 카메라 권한을 거절해도 초대 붙여넣기를 사용할 수 있습니다.

QR에는 주소·인증서 지문·일회용 초대 토큰·만료 시각이 들어 있습니다. 기기 접근 토큰이나 라이브러리 전체는 포함하지 않습니다. QR을 읽어도 원본 폰의 승인이 필요합니다. 코드를 양쪽에서 비교한 뒤 승인하세요. 만료·다른 종류의 QR은 반려하며, QR 안의 일반 웹 주소를 자동으로 열지 않습니다. QR 사진은 초대와 마찬가지로 비밀로 전달해야 합니다.

이 QR은 네트워크 초대 주소로 연결합니다. QR 자체가 네트워크를 만들지는 않습니다. Wi-Fi/직접 도달 가능한 주소가 없는 경우에는 아래의 Bluetooth 기기 검색으로 연결하세요. Android는 일반 앱에 자기 Bluetooth MAC 주소를 제공하지 않으므로 QR에 임의의 MAC 주소를 넣지 않습니다.

## 초대 복사 없이 근처 기기 연결

음악 서버를 켠 폰에서 **Wi-Fi에서 2분간 기기 공개**를 누르고, 상대 폰은 **연결하기 → 같은 Wi-Fi 기기 찾기**를 누릅니다. 나타난 기기 이름을 누르면 초대 복사 없이 승인 요청이 전송됩니다. 양쪽의 확인 코드를 직접 비교한 다음 원본 폰에서 승인하세요. 공개는 2분 뒤 또는 화면을 나가면 중지하며, 음악 서버를 중지해도 끝납니다. 검색은 최대 30초, 결과는 최대 32대입니다. 공유기의 AP 격리·mDNS 차단 환경에서는 수동 초대를 사용하세요.

### Wi-Fi 없이 Bluetooth로 전송

음악 서버 폰에서 **Bluetooth에서 2분간 기기 공개**를 누른 뒤 Android 기기 공개 확인을 허용합니다. 듣는 폰에서는 **Bluetooth 기기 찾기**를 눌러 원본 폰을 고릅니다. 목록에는 일반 Bluetooth 기기도 표시될 수 있으므로 T2Rhythm에서 공개한 폰을 선택하세요. 최초 연결에는 Android의 근처 기기 권한과 시스템 페어링 확인이 필요할 수 있습니다. Android 11 이하는 검색에 위치 권한이 필요합니다.

이 경로는 Bluetooth Classic RFCOMM으로 음원을 직접 전송하므로 Wi-Fi나 인터넷이 없어도 사용할 수 있습니다. Bluetooth 오디오 헤드폰으로 출력하는 기능과는 별개입니다. 기존 TLS·기기 승인·구간 탐색·접근 취소·개인 스트림 캐시 정책을 그대로 사용합니다. 내부 `bt-…t2rhythm.invalid` 주소는 앱 전용 Bluetooth 경로이며 브라우저나 DNS에서 열 수 있는 주소가 아닙니다.

기기 공개가 끝나도 이미 승인된 연결은 음악 서버가 켜져 있는 동안 재생할 수 있습니다. 서버 중지는 Bluetooth 전송도 끊습니다. 폰의 Bluetooth를 끄거나 앱을 강제 종료하면 연결이 끝나며, 서버를 다시 켠 후 Bluetooth 공개를 눌러 전송 경로도 다시 켜야 합니다. 기기 공개 버튼은 새 초대만 닫습니다. 연결한 기기를 차단하려면 **접근 취소**, 모든 전송을 끝내려면 **음악 서버 중지**를 사용하세요.

Wi-Fi와 Bluetooth 사이에서 경로를 바꾸려면 원본 폰에서 원하는 방식으로 다시 공개하고 듣는 폰에서 그 기기를 다시 선택하세요. 이미 연결한 기기는 기존 인증서와 승인 정보를 검증한 뒤 주소만 갱신합니다. 연결 실패 시 기존 주소를 보존합니다. 자동으로 승인되지 않은 다른 기기로 바꾸지 않습니다.

Bluetooth 전송 속도와 동시 연결 수는 두 폰·제조사·주변 무선 간섭에 영향을 받습니다. 고음질 무손실 파일·여러 동시 재생에는 Wi-Fi를 권장합니다. 서로 다른 실제 폰에서의 Bluetooth 처리량·OS 페어링 동작은 기기 검증이 필요합니다.

## 밖에서 연결하기

T2Rhythm은 두 폰 사이에서 도달 가능한 네트워크를 사용합니다. 가장 간편한 방법은 두 폰을 사용자가 관리하는 같은 개인 VPN에 연결하는 것입니다. WireGuard, Tailscale 등에서 서버 폰의 VPN 주소를 확인한 다음 그 주소와 포트 **8898**을 초대에 입력합니다.

이미 연결한 서버라면 **주소 변경**에서 새 VPN 주소를 입력하세요. 예: `https://100.90.80.70:8898`. 주소가 달라져도 기존 서버 인증서가 일치하는지 확인한 뒤 저장합니다. 서버의 VPN 주소나 개인 DNS 이름을 유지하면 매번 초대할 필요가 없습니다.

사용자가 직접 설정한 라우터/IPv6 경로도 이용할 수 있습니다. 외부 포트와 내부 8898 포트가 연결되어 있어야 합니다. 앱은 공유기 포트를 자동으로 열거나 공인 IP를 조회하지 않습니다. 통신사의 CGNAT, 방화벽, VPN 접근 정책에 따라 직접 연결은 불가능할 수 있습니다. T2Rhythm 자체에는 중앙 서버나 우회 중계가 없으며 VPN 서비스의 운영 방식은 각 서비스에 따릅니다.

## 여러 기기가 함께 쓰기 (1324 이상)

각 폰은 자신의 서버를 실행하면서 다른 폰의 음악을 동시에 들을 수 있습니다. 서로의 초대를 교환하고 각 폰에서 승인하세요. 하나의 폰에 최대 8대의 음악 서버를 등록할 수 있고, 각 서버도 최대 8대의 기기를 승인합니다. 어느 폰을 중앙 서버로 정할 필요가 없습니다.

**연결하기 → 모든 기기**에서 여러 기기의 음악을 함께 검색하고 재생·셔플할 수 있습니다. 출처가 곡마다 표시되며, 기기 이름을 선택하면 그 기기만 봅니다. 꺼진 기기는 따로 표시하고, 연결되는 다른 기기의 결과를 계속 사용할 수 있습니다. 기기 추가와 주소 변경·연결 해제는 기기 관리에서 합니다.

공유할 때 **플레이리스트 선택**에서 여러 개를 체크하고 적용하세요. 해당 목록의 이름과 곡 순서를 함께 공유합니다. 이후 ‘기기의 모든 음악’을 누르면 전체 음악도 공유하면서 선택한 목록을 함께 제공할 수 있습니다. 음악·플레이리스트의 변경과 이름·순서 변경은 서버가 켜져 있는 동안 반영됩니다. 공유 설정 자체를 바꾸려면 서버를 중지하고 다시 선택해 실행하세요.

다른 폰의 **플레이리스트**에서 목록을 열어 곡을 확인하고 바로 재생하거나 **보관함에 담기**로 새 목록 또는 기존 목록에 담습니다. 개별 곡이나 현재 불러온 여러 기기의 곡도 같은 방법으로 담을 수 있습니다. 저장한 목록은 복사본이며 원본 목록의 이후 편집을 자동으로 덮어쓰지 않습니다.

여러 기기의 곡이 섞인 목록도 출처를 보존해 공유합니다. 음원이나 다른 기기의 인증 정보를 중간 폰이 다시 제공하지 않습니다. 받는 폰이 원래 음악을 보관한 기기와 연결·승인되어 있어야 그 곡을 들을 수 있습니다. 자신의 음악을 포함한 목록을 다시 받으면 로컬 원본으로 재생합니다. 아직 연결하지 않은 기기의 곡은 연결이 필요하다고 표시하고, 목록을 먼저 저장할 수도 있습니다. 저장한 뒤에는 목록을 전달해 준 폰이 꺼져도, 원래 음악이 있는 기기와 연결되면 해당 곡을 재생할 수 있습니다.

공유 목록은 최대 100개, 목록마다 최대 5,000곡을 제공하며 초과 시 화면에 표시합니다. 여러 기기의 검색 결과는 기기마다 최대 2,000곡을 유지하고 더 많은 곡은 검색·필터로 찾습니다. 목록을 담아도 음원 파일을 내려받아 보관하는 것은 아닙니다.

## 음악·캐시·기기 관리

- 곡·아티스트·앨범·장르 검색은 서버의 현재 라이브러리를 대상으로 합니다. 목록은 100곡씩 불러오며 재생 버튼에는 현재 표시한 곡 수가 표시됩니다. 한 목록에 최대 2,000곡을 유지하고, 더 많은 곡은 서버 검색과 장르 필터로 찾습니다.
- 공유받은 음악의 실제 재생은 평소 청취 기록과 통계에 포함됩니다. 연결이 저장된 서버의 곡은 청취 보고서에서도 다시 재생하거나 플레이리스트로 담을 수 있습니다.
- 음악 정보가 바뀌면 서버의 Room 변경을 반영하고 목록 버전을 바꿉니다. 클라이언트의 **라이브러리 새로고침**으로 즉시 반영하며, 화면을 보고 있는 동안에는 주기적으로 변경도 확인합니다. 다음 페이지를 읽는 도중 버전이 바뀌면 목록을 처음부터 새로 가져와 서로 다른 버전이 섞이지 않게 합니다.
- 음원은 전체 복사 없이 필요한 바이트 구간을 전송합니다. 메인 플레이어와 사전 로딩 모두 개인 음악 서버의 인증된 경로를 사용하며 일반 음원 디스크 캐시를 거치지 않습니다. 앨범 표지의 작은 미리보기는 앱의 이미지 캐시를 사용할 수 있습니다.
- 서버 폰의 **접근 취소**는 해당 기기의 새 요청을 차단하고 진행 중인 음원 전송을 끊습니다. 재생 기기에 이미 전달되어 메모리에 버퍼된 부분까지 회수할 수는 없습니다.
- 연결한 폰의 **연결 해제**는 로컬 인증 정보를 지우고 현재 재생을 일시 정지합니다. 서버에도 연결 해제를 요청하며, 서버가 꺼져 있다면 서버 폰에서 별도로 접근을 취소할 수 있습니다.
- 공유할 범위는 서버를 중지한 뒤 다시 고릅니다. 1324부터 선택한 플레이리스트의 곡 추가·삭제와 순서 변경은 실행 중에도 반영합니다. 1323의 로컬 곡 선택은 시작 당시 범위를 사용합니다.
- 연결 승인 정보는 서버 재시작 후에도 유지됩니다. 초대와 아직 승인하지 않은 요청은 서버를 중지하면 폐기합니다. 앱 삭제/데이터 초기화 후에는 다시 연결해야 합니다.

## 전원과 실행

서버를 실행하면 지속 알림이 표시되고 폰을 깨워 연결을 유지합니다. 알림의 **서버 중지**나 앱의 중지 버튼으로 언제든 끝낼 수 있습니다. 서브폰은 충전기에 연결해 두는 것이 좋습니다. 충전하지 않고 배터리가 15% 아래로 내려가면 서버를 중지합니다.

Android와 제조사의 절전 정책, 네트워크 전환, VPN 종료, 앱 강제 종료로 연결이 끊길 수 있습니다. 폰을 다시 켜거나 앱을 강제 종료한 뒤 서버를 자동으로 공개하지 않습니다. 필요할 때 앱을 열고 서버를 다시 실행하세요. 원본 형식 그대로 전송하므로 대용량 무손실 음원은 그에 맞는 네트워크 속도와 데이터가 필요합니다.

## 보안 경계

음악 목록·표지·음원에는 승인된 기기 인증이 필요합니다. 브라우저에서 열 수 있는 공개 음악 페이지, 업로드, 파일 경로 접근, 검색 엔진용 목록을 제공하지 않습니다. 앱 내부의 서버 개인 키는 Android Keystore에서 내보낼 수 없으며, 클라이언트 연결 토큰은 Keystore 키로 암호화해 시스템/앱 백업에서 제외한 영역에 보관합니다. 서버는 토큰 원문 대신 해시를 저장합니다.

1325의 새 초대와 근처 발견 연결은 인증서 지문과 연결 토큰을 함께 반영한 16자리 확인 코드를 네 묶음으로 표시합니다. 공개된 발견 정보를 악성 기기가 바꾸더라도 다른 인증서로 연결한 폰의 코드는 원본 폰과 달라집니다. 이전 버전에서 직접 전달받은 초대의 여섯 자리 확인은 수동 초대 호환용으로 유지합니다. 새 근처 검색과 Bluetooth 연결은 양쪽 폰을 1325 이상으로 업데이트해야 합니다.

### 공인 인증서가 없어도 HTTPS를 쓰는 이유

공인 인증기관은 웹 브라우저가 도메인 소유자를 확인할 때 필요합니다. T2Rhythm은 폰의 Android Keystore에서 자체 인증서를 만들고, 초대에 담긴 SHA-256 인증서 지문과 실제 TLS 서버 인증서가 같은지 직접 검증합니다. 인증서 유효기간도 확인하며 다른 인증서를 모두 허용하는 trust-all 방식이 아닙니다. 서버 키는 폰 밖으로 내보내지 않습니다. 공인 도메인·유료 인증서·중앙 인증기관 없이 사용할 수 있지만, 일반 브라우저가 신뢰하는 웹사이트라는 의미는 아닙니다.

근처 검색은 기기를 발견하는 방법이며 발견한 이름 자체를 신뢰하지 않습니다. 공개 중에는 주변 기기도 승인 요청용 초대 정보를 받을 수 있지만, 목록과 음원은 원본 폰에서 승인해야 열립니다. 같은 네트워크에 악성 기기가 있을 수 있으므로 **양쪽 폰에 표시한 코드가 일치하는지 직접 확인**해야 합니다. 표시 이름만 보고 승인하지 마세요.

초대는 비밀이며 믿을 수 있는 경로로 전달해야 합니다. 인증은 승인한 기기가 음악을 요청할 수 있게 하는 방식입니다. 기기가 탈취되거나 승인받은 사용자가 음악을 별도로 녹음·복사하는 것, 특정 기관의 접근을 모든 상황에서 막는 것을 보장하는 기능은 아닙니다.

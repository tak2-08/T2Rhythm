# 1329: 재생 우선 실행과 선택적 AI

전체 플레이어는 열기 동작·위로 끌어올리기·닫힘 애니메이션 동안만 구성합니다. 접힌 뒤에는 전체 화면의 Compose 구독과 효과를 해제하고, 저장 가능한 UI 상태는 유지합니다. 미니 플레이어가 이미 사용하는 현재 곡과 아트워크를 재사용합니다. 홈·보관함·주 내비게이션·Activity의 상태 구독은 화면 생명주기를 따릅니다.

앨범·아티스트 필터 투영은 이를 표시하는 목적지에서만 구독하며, 빠른 재진입을 위한 5초 대기 후 계산을 중단하고 30초 후 보관된 투영을 비웁니다. 재생 명령에 필요한 공통 곡 목록과 기본 앨범 목록은 유지합니다. 프리로드는 전체 큐를 복사하지 않고 Media3의 실제 셔플·반복 순서에서 다음 최대 2곡(저사양 기기 1곡)의 로컬 소스만 준비합니다. 바뀐 소스는 제거하고 원격 음원은 미리 요청하지 않습니다.

자동 분석은 서비스의 재생·버퍼링 신호를 확인하여 미룹니다. 자동 추천 갱신, 아카이브 마이그레이션과 자동 태그·가사 쓰기도 재생과 경쟁하지 않도록 기다립니다. 명시적인 편집·분석 요청과 청취 기록은 유지합니다. UI가 없으면 진행률 확인 간격을 100ms에서 500ms로 낮추되 외부 가사 전달은 계속합니다. Android의 실행 중 메모리 부족 단계 5/10/15에서도 일회성 아트워크 캐시를 정리합니다. 실제 기기별 버벅임·강제 종료의 개선 폭은 같은 음원·대기열·기기에서 측정해야 하며, 소스 변경만으로 모든 종료 원인이 해결되었다고 판단할 수 없습니다.

## AI 연결과 표시

설정 → AI 연결에서 Google AI Studio, Groq, Cerebras, Hugging Face, OpenAI API, Anthropic API와 xAI API를 추가합니다. 같은 제공자의 여러 모델·키도 개별 연결로 등록할 수 있으며, 현재 제공자가 지원하는 모델 이름을 직접 입력할 수 있습니다. 서비스 구독과 API 요금·제공 모델은 별개입니다.

각 연결의 선택 여부와 위·아래 순서를 지정합니다. 기본은 우선순위 순서로 실패 시 폴백하며, 요청마다 시작 연결을 순환하는 옵션도 있습니다. 각 연결은 한 요청에 한 번 시도합니다. 연결별 호출 제한은 22초, 전체 요청은 65초입니다. HTTP 429의 Retry-After(최대 5분), 인증 오류(5분), 기타 오류·잘못된 응답(15초)에는 대기 시간을 적용합니다. 취소하면 다음 제공자에게 넘어가지 않습니다. 쿨다운 중인 연결은 건너뛰므로 전체 제한 안에 모든 연결을 시도하지 못할 수 있습니다. 자동 백그라운드 호출은 없습니다.

연결을 저장하고 AI 기능을 켠 경우에만 홈에 작은 AI 아이콘이 생깁니다. 꺼져 있으면 설정 외의 AI 안내·자리표시자·배너가 없습니다. 홈은 작은 사용 가능 표시만 읽으며 키를 복호화하거나 HTTP 클라이언트를 만들지 않습니다. 키는 Android Keystore의 AES-GCM 키로 암호화하여 noBackupFilesDir에 저장합니다. 로그·일반 설정·내보내기·백업에 키를 넣지 않습니다.

## 요청·검토·실행

플레이리스트·곡·앨범 추천, 장르 찾기, 보관함 정보 수정, 휴지통 이동 후보와 공유 목록을 요청할 수 있습니다. 장르·입력 문구·기기 내 좋아요로 최대 120곡의 후보를 선택합니다. 좋아요 여부 자체는 전송하지 않습니다. 사용자가 상황을 직접 쓰거나 기존에 선택적으로 수집한 시간·월·날씨·이동 종류만 불러올 수 있습니다. 새로운 위치·마이크·센서 권한을 요청하지 않습니다.

전송 전에 실제 JSON과 선택한 제공자를 보여 주고 확인합니다. 곡의 임시 ID·곡명·아티스트·앨범·장르·길이와 입력 내용만 전송합니다. 음원·가사·파일 경로·좌표·청취 기록을 자동으로 보내지 않습니다. 입력 문구에 사용자가 넣은 내용은 그대로 전송됩니다. 폴백을 켜면 같은 내용을 다른 선택 제공자에게 보낼 수 있다는 안내도 확인합니다. 제공자별 데이터 처리 정책은 해당 API의 정책을 따릅니다.

응답은 요청한 작업과 최대 40개의 실제 후보 ID만 허용합니다. 알 수 없는 필드·명령·다른 작업·중복 ID·후보 외 ID·초과 응답·잘린 응답·도구 호출은 실행하지 않습니다. 제목과 설명은 일반 텍스트로 표시합니다. 모델은 파일·권한·키·실행 도구에 접근하지 않습니다.

- 재생과 플레이리스트 저장: 사용자가 곡을 선택하고 실행합니다. 기존 재생·플레이리스트 기능을 사용합니다.
- 정보 수정: 곡마다 전후 차이를 확인한 뒤 보관함의 수동 메타데이터로 적용합니다. 원본 음원의 태그·이름·내용은 건드리지 않습니다. 적용 전 작은 원본/결과 기록을 원자적으로 저장하며, 앱 재시작 후에도 되돌리기를 제공합니다. 현재 정보가 검토 당시와 다르면 덮어쓰지 않습니다. 실제 파일 태그 편집은 기존 앱의 명시적 편집 기능을 이용합니다.
- 휴지통: Android 11+의 MediaStore 음원에만 시스템 휴지통 확인창을 사용합니다. 지원하지 않는 기기·파일에 영구 삭제로 우회하지 않습니다. 복구 가능 기간과 복구 화면은 시스템 정책을 따릅니다.
- 공유: 선택한 곡명·아티스트·앨범 목록을 시스템 공유창에 전달하며, 사용자가 수신 앱과 대상을 선택합니다. 자동 전송하지 않습니다.

## 검증과 남은 확인

JVM 검증은 AI의 후보 밖 ID·권한 범위 확대·파일 경로/명령 필드·과도한 입력/응답·잘못된 수정 필드, 제공자 선택·순서·순환·폴백·429 대기·취소, 10만 곡 큐에서 최대 두 곡만 확인하는 프리로드를 다룹니다. 기존 음악·카탈로그·런타임 회귀와 Android lint도 실행합니다. 검토 빌드는 기존 원본 APK 인증서와 고정된 프로덕션 모듈 서명을 사용하며, 공개 릴리스 생성이나 main 병합은 수행하지 않습니다.

실제 API 키를 사용한 제공자별 호출, 물리 기기의 장시간 재생·메모리·발열 비교는 별도 확인이 필요합니다. 기본 모델 예시는 제공자 변경에 따라 수정할 수 있습니다. 추가로 발전시킬 기능은 기기 안에서 요약한 취향 설명의 선택적 전송, 중복 음원 정리 후보, 앨범 메타데이터 일괄 차이 검토입니다. 현재의 한 번 요청·검토·명시 실행 경계를 유지하는 방향을 권장합니다.

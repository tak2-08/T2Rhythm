# 앱 전반 개선 — 2026-10-26

검색 화면 외에 재생 대기열, 플레이리스트 입출력, 다운로드 목록, 설정 검색, 여러 기기의 스트리밍 목록을 점검했습니다. 업데이트의 파일 무결성 검사와 설치 기록도 읽어 확인했으며 이번 변경에서 수정하지 않았습니다.

## 재생 대기열

- 셔플 해제 시 ID 집합으로 다음 곡을 복원하던 처리를 곡의 등장 횟수를 소비하는 방식으로 바꿉니다. 중복 곡이 늘어나거나 사라지지 않고, 이미 재생한 구간과 현재 곡을 유지합니다.
- 복원할 때 예전 원본 목록의 객체 대신 현재 대기열의 객체를 사용하므로 갱신된 제목·메타데이터를 유지합니다. 셔플 중 추가한 항목도 남습니다.
- 대기열/플레이리스트 UI의 항목 키 추적에서 반복 선형 탐색을 제거합니다. 같은 ID의 항목은 기존 순서대로 키를 할당합니다.
- 무작위 300개 대기열의 항목 수 보존, 5만 곡에서 키 조회 수가 선형인지 검사하는 회귀 테스트를 추가합니다.

- 실제 플레이어 인덱스를 우선 사용해 같은 곡의 두 번째 항목을 재생 중일 때 첫 번째 항목으로 이동하지 않도록 합니다.

## 플레이리스트 가져오기·내보내기

- M3U의 BOM·들여쓰기·CRLF, PLS의 대소문자 혼합 키·공백·순서가 섞인 항목을 지원합니다. 잘못된 항목 번호는 제외합니다.
- 제목·가수가 같더라도 URI가 다른 스튜디오/라이브 음원을 각각 보존합니다. 같은 URI의 중복은 기존 보관함 모델에 맞춰 한 번만 추가합니다.
- 가져오기에 필요한 URI/파일명 색인을 가져오기 작업당 한 번만 구성합니다. 대소문자 비교는 기기 언어의 영향을 받지 않게 합니다.
- 내보내기 파일명에 한글을 유지하고, 경로 구분자 등 파일명에 부적절한 문자와 길이는 기존 FileNamePolicy로 처리합니다.
- 동일한 이름이나 정리 후 같은 이름이 된 플레이리스트에도 고유 ZIP 항목명을 부여해 덮어쓰기/중복 ZIP 오류를 방지합니다.
- 사용자가 선택한 폴더로 전체 내보내기를 할 때 실제 ZIP 한 개를 생성합니다. 실패한 문서와 임시 파일은 정리합니다.

## 다운로드

- 최초 로딩 중 빈 목록 안내가 표시되지 않도록 구분합니다.
- 목록 조회가 실패하면 화면을 닫지 않고 재시도할 수 있습니다.
- 손상되거나 필수 정보가 빠진 앨범 기록은 개별적으로 건너뜁니다. 하나의 잘못된 JSON이 전체 목록을 막지 않게 합니다.

## 스트리밍

- 다음 페이지 요청 실패를 최초 연결 실패와 구분해 이미 받은 곡을 유지합니다.
- 오류가 난 서버만 다시 시도할 수 있습니다. 페이지 재시도는 같은 위치에서 시작합니다.
- 새 검색으로 전환한 뒤 오래된 응답이 도착해도 새 결과를 덮어쓰지 않는 회귀 테스트를 추가합니다.
- 자동 변경 확인 중 사용자가 추가 요청을 시작하면 중복 갱신을 피합니다.

## 설정 검색

- 입력한 모든 단어를 제목·설명·키워드·상위 설정 화면에서 함께 확인합니다. 단어 하나만 맞아서 무관한 설정이 나타나던 동작을 수정합니다.
- 한글 초성/혼합 검색과 전각 문자 정규화를 공통 검색 색인으로 지원합니다.
- 정규화된 색인은 검색 입력마다 만들지 않고 설정 목록이 바뀔 때만 재생성합니다.

## 실제 화면에서 확인한 번역 누락

이전 검증 커밋의 Android 스크린샷에서 한국어 아티스트 화면의 `0 albums · 1 tracks`와 업데이트 화면의 `Version:` 문구를 확인했습니다. 아티스트의 앨범·곡 수와 앨범 카드의 곡 수는 기존 복수형 리소스로, 업데이트의 버전·출시일 안내는 기존 번역 리소스로 통일합니다. 한국어 버전 접두어도 `브이`에서 `v`로 정리합니다.

## 키보드가 열린 검색 화면

실제 Android 화면 검토에서 검색창이 키보드에 가려지거나, 화면 재생성 뒤 입력창과 탭이 화면 위로 밀리는 문제를 확인했습니다. 검색 목록과 하단 조작부가 같은 가용 높이를 사용하도록 하고, 바깥의 독립된 레이아웃에서 검색 화면의 크기를 측정합니다. 여백을 주는 안쪽 레이아웃을 측정해서 크기와 여백이 서로 바뀌는 순환을 방지합니다.

Android 11 이상은 명시적인 IME 인셋과 `adjustNothing`을 사용합니다. 이전 버전은 이미 줄어든 창을 고려한 표시 영역 측정과 `adjustResize`를 사용하며, 검색 중에만 decor fitting을 켭니다. 검색을 닫으면 원래 창 모드와 레이아웃 플래그를 복원하고 현재의 밝은/어두운 시스템 바 설정을 유지합니다. 전체 곡 목록을 열 때는 검색창의 포커스를 해제합니다.

Compose가 IME 여백을 반영하기 전에 입력창의 이전 위치를 Android에 전달하면, Android가 앱의 여백 처리와 별도로 창 전체를 이동시킬 수 있습니다. 검색 루트는 하위 스크롤 목록이 위치 요청을 처리한 후 자신의 전체 영역을 상위에 전달합니다. 오래된 입력창 좌표가 창 전체를 밀어 올리는 경로를 막으면서 목록 내부의 항목 스크롤은 유지합니다.

기기 검사는 실제 키보드를 열고 화면을 재생성한 뒤에도 입력창이 키보드 바로 위에 있고, 탭과 일치하는 곡이 실제 표시되는지 확인합니다. Android 10·15·17의 별도 CI에서 같은 시나리오를 세 번씩 실행하며, 실패 시 창 모드·좌표와 화면을 남깁니다. 실행 건수와 모든 반복의 성공을 요구합니다. Android 15 일반 에뮬레이터에는 기존 검사와 같은 KVM MSR 호환 설정을 적용합니다.

전체 경험 회귀 검사는 3 GB RAM과 512 MB 힙을 명시합니다. 클래스 하나가 실패해도 나머지를 실행해 결과를 모으고, 실패하거나 누락된 검사가 있으면 배포를 차단합니다.

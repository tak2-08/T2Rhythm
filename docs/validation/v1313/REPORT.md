# 5.5.499.1313 검증 기록

## 환경과 범위

Android API 29 x86_64 에뮬레이터, 720×1280, 320dpi에서 실제 SQLite·WorkManager·MediaStore와 앱의 Compose 구성 요소를 검증했습니다. 다운로드 화면은 기본 글꼴, 완료 안내·보존 안내는 1.3배 글꼴로 확인했습니다. 화면은 테스트 Activity에서 실제 구성 요소를 실행한 캡처입니다. 전체 탐색 흐름이나 삼성 기기의 성능 측정 결과를 뜻하지 않습니다.

## 자동 검증

- 앱 271개 + 크롤러 52개, 단위 테스트 323개 통과.
- Android 38개 회귀 묶음 통과 후 최종 변경 관련 8개 재검증 통과. 중복 7개를 제외한 검증 항목은 총 39개입니다.
- 일괄 작업의 이전/이후 입력 지문, 새 곡·수동 수정·설정 변경, 기존 완료 이력 이전과 실패가 섞인 이전 작업의 보수적 처리를 확인했습니다.
- 실패·취소 항목의 다운로드/이어받기/HLS 파일과 기록을 함께 삭제하고, 늦은 작업 콜백이 항목을 되살리지 않는지 확인했습니다. 실제 MediaStore에서 기록에 URI가 없는 미완성 파일은 지우고, 같은 작업 ID의 게시 완료 파일은 보존하는지 검증했습니다.
- 이전 충전·유휴 대기 작업의 ID를 유지한 조건 변경과 자동 정리의 20분 초기 지연을 실제 WorkManager에서 확인했습니다. 배터리 90% 경계와 부하·발열·절전 조건은 단위 테스트, 충전하지 않은 낮은 배터리에서의 중단은 Android에서 검증했습니다.
- 요약 전후 재생 횟수·청취 시간·곡별 누적 취향·최초 완청 시점이 일치했습니다. 최근 120일 기록 파일이 바뀌지 않고, 예전 원본과 요약본을 반복 가져와도 중복 계산하지 않으며, 데이터베이스 삭제 후 요약 저널만으로 다시 복구되는지 확인했습니다.
- 추천 요약의 학습 특징값·반응 취소 정보, 구간 사이 공백 보존, 백업의 같은 기록 포함 여부·새 기록·잘못된 형식 거부도 확인했습니다.
- 기존 PCM 지문·파형, 장르·가사 제안, 한국어 Vosk 모델/JNA 로딩과 침묵에서 가사를 만들지 않는 회귀도 통과했습니다.

하드웨어 가속 없는 에뮬레이터의 CPU 부하가 높아 최초 분석 테스트들이 `AnalysisDeferred`로 양보했습니다. 분석 보호 기능을 유지한 채 테스트에서 이 경우에만 저부하를 기다려 독립된 테스트를 다시 실행하도록 했습니다. 일반 검증 실패는 재시도하지 않습니다. 검증 중 Android 10이 기본 조회에서 미완성 파일을 숨기는 동작을 발견해, API별로 미완성 파일 포함 조회를 적용했습니다. 이미 삭제한 테스트 파일을 정리 단계에서 다시 지우던 테스트 오류도 수정했습니다.

GitHub 전체 Lint에서 안내의 `90%`를 서식 코드로 해석하는 문자열 오류 16건을 발견했습니다. 문구 내용은 유지하고 영문·한국어의 해당 문자열에 `formatted="false"`를 명시했습니다. 수정 후 전체 CI와 최종 APK를 다시 검증합니다.

## 보존과 한계

정리 중 중단·원본 재가져오기·데이터베이스 재생성에 대한 복구를 검증했습니다. 백업의 이전 상세 버전은 기록 포함 여부와 게시 파일의 SHA-256을 확인한 경우에만 정리합니다. 포함 여부 증명은 메모리 상한을 두며, 증명할 수 없는 파일은 보존합니다. 완료 이력 데이터베이스가 없는 다른 기기에서 복원하면 일괄 조회를 다시 할 수 있습니다.

삼성 Android 17 실기기에서의 장시간 부하·배터리·시스템 백그라운드 제한은 이 환경에서 측정하지 않았습니다. 최종 서명 APK의 소스 식별·서명·16KB 정렬·R8 네이티브 실행과 GitHub CI 결과는 PR 및 릴리스 게시 단계에서 별도로 확인합니다.

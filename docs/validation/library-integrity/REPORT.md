# 이미지·영상 보존과 개인 음악 경험 검증

## 현재 검증 상태

- 로컬 앱 단위 테스트 278개, 크롤러 단위 테스트 52개 통과.
- 최종 APK 빌드·Lint·Android 회귀 묶음은 실행 중이며, 결과가 확정되면 이 문서를 갱신합니다.
- 이미지·영상·가사·보고서·믹스의 Android 회귀 테스트와 GitHub의 가속 에뮬레이터 실행 경로를 추가했습니다.

로컬 관리 환경에는 `/dev/kvm`이 없어 Android API 29 x86_64 기기를 소프트웨어 에뮬레이션으로 실행했습니다. 초기 부팅과 시스템 서비스 재시작이 매우 느려, GitHub의 KVM 기기에서 별도로 재현할 수 있게 했습니다. 환경 지연을 앱 기능 통과로 간주하지 않습니다.

## 검증하는 동작

1. 수동 이미지와 이전 URI 영상 연결을 영구 기록으로 이전한 뒤 실제 Room 테이블을 비우고, MediaStore ID가 바뀌어도 선택과 연결을 찾습니다. 다른 파일의 ID 재사용·내장 이미지 재추출·명시적 이미지 삭제도 확인합니다.
2. 연결 없는 영상 파일을 발견해 두 곡에 연결하고, 실제 파일 삭제 시 모든 공유 연결을 제거하며 뒤늦은 다운로드가 복구하지 못하는지 확인합니다.
3. 실제 MediaStore에 음원을 게시하고, 라이브러리 스캔 전 완료 파일을 재생 가능한 Song으로 해석합니다. 미완성·누락 파일을 거절합니다.
4. 가사 제안의 시간만 조정하며 원본 가사와 최초 예측을 보존합니다. 잘못된 줄 순서를 거절하고, 파형 초안·무음 거절·중복 PCM 제한·장르별 제한을 확인합니다.
5. 주·월·분기의 윤년/연도 경계와 DST, 기간 경계의 실제 청취량을 확인합니다.
6. 다운로드 검색 탭·알고리즘 관리·청취 보고서를 실제 Compose 구성 요소로 실행하고 화면을 저장합니다. 실제 로컬 AAC 구간의 믹스 미리 듣기가 종료되고 별도 음원을 생성하지 않는지 확인합니다.
7. 기존 아트워크 재로딩과 비동기 메타데이터 병합 회귀를 함께 실행합니다.

화면에 쓰는 청취 곡과 기록은 재현 가능한 테스트 자료입니다. 실제 사용자 청취 기록을 공개하지 않습니다.

## 재현

```sh
./gradlew :crawler:test :app:testGithubDebugUnitTest
./gradlew :app:lintGithubDebug :app:assembleGithubDebug :app:assembleGithubDebugAndroidTest
bash scripts/run_personal_experience_regression.sh
```

마지막 명령은 시작된 Android 기기와 `adb`가 필요합니다. GitHub의 **Personal experience regression** 작업이 APK를 빌드하고 API 29 기기를 시작해 같은 명령을 실행합니다. 테스트 XML·HTML, 기기 로그, 화면 PNG는 `personal-experience-regression` 아티팩트에 보관합니다.

실기기에서의 장시간 배터리 소모와 외부 제공처의 모든 검색 결과·지역별 이용 가능성까지 이 회귀 묶음이 검증하는 것은 아닙니다. 가사 검증 오차는 참고 LRC와의 일치도이며 보컬의 정답률을 뜻하지 않습니다.

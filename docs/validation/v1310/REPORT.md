# T2Rhythm 5.5.499.1310 검증 기록

실제 MainActivity와 앱의 탐색 코드를 Android API 29 에뮬레이터에서 실행했습니다. 720×1280px·320dpi, 한국어, 기본 글꼴과 시스템 글꼴 배율 1.3을 사용합니다. 화면의 곡·앨범 이름과 커버는 재현 가능한 테스트 데이터이며 실제 인기 순위가 아닙니다.

## 화면과 조작

- 인기 리스트는 기존 접히는 헤더와 Material 3 목록을 사용합니다. 출처·갱신 시점·순위 기준·새로고침을 분리하고, 다운로드는 기존 출처 선택 창으로 연결합니다.
- 떠 있는 탐색 막대와 고정 탐색 막대에서 인기 탭을 열고 미니 플레이어를 유지합니다. 보관함을 거쳐 다시 인기 화면으로 이동하는 경로도 검사합니다.
- 앨범을 눌러 해당 곡으로 좁힌 뒤 ‘전체 곡 보기’로 해제합니다. 파일 주소 입력과 취소를 실제 버튼으로 검사합니다.
- 큰 글꼴에서 5개 탐색 항목 중 ‘라이브러리’가 잘리는 것을 확인해 탐색 막대의 이름만 ‘보관함’으로 줄였습니다. 화면 제목은 기존 명칭을 유지합니다.
- 캡처 전에는 활성 접근성 창이 앱 소유인지 확인해 시스템 대화상자가 가린 화면을 통과로 기록하지 않도록 했습니다.

## 데이터와 회귀 검증

- **단위 테스트 304개**: 앱 252개·크롤러 52개. 인기 순위 가중치·복수 출처·중복 방지·버전 구분, 완청 보호·연속 반복·쓰기 대기열, 스트리밍 통계의 구간 중복·자정·서머타임·조용한 날을 포함한 평균을 확인합니다.
- **Android 고유 사례 53개**: 기존 플레이어·영상·백업·맥락·다운로드·화면 47개, 새 영속성 사례 5개, 실제 MainActivity 탐색 사례 1개입니다. 전체 실행에서 기존 및 새 데이터 사례 52개가 통과했으며, 탐색 사례도 테스트 구성 수정 후 별도 실행에서 통과했습니다.
- 기존 버전 2의 풍부한 청취 기록을 버전 3으로 이전하고, 완청 근거와 실제 청취 비율을 재시작 뒤에도 유지하는지 확인합니다. 기록 삭제 뒤 이전 세대 통계 캐시가 다시 채택되지 않는지도 검사합니다.
- 자동 볼륨 콜백 10,000번이 기록 폭주를 만들지 않는지 검사합니다. 백업 복사 확인 값 1,000개를 SQLite로 이전하면서 폴더 설정을 보존하는지도 확인합니다.
- 통계 집계기에 기록 100,000개를 순서대로 공급하여 전체 이벤트 목록 없이 결과를 만드는 사례를 검사합니다. 이는 삼성 실기기 성능 측정 수치를 뜻하지 않습니다.
- 저장한 실제 차트 HTML은 벅스 100개·멜론 100개·지니 50개를 파싱합니다. 인기 100곡 중 복수 사이트에 나타난 곡은 76곡이었습니다. 이 검증을 위해 같은 사이트에 반복 요청하지 않았습니다.

## 테스트 중 확인한 한계

최초 단독 MainActivity 화면 실행에서는 테스트 가상 시계가 초기화 중의 Compose 레이아웃을 계속 진행해 시스템 서비스 응답 제한에 걸렸습니다. Android 덤프의 메인 스택은 `TestMonotonicFrameClock` → `ComposeIdlingResource` → `RectManager`였습니다. 이 화면 사례를 실제 Android 시계로 동작하는 ActivityScenario와 UiAutomation 조작으로 옮겼습니다. 앱별 언어 설정과 다른 계측 컨텍스트의 영어 문구를 읽던 부분도 실제 Activity의 한국어 리소스를 사용하도록 바로잡았습니다. 최종 실행에서는 추가 ANR 기록 없이 6개 화면과 조작이 통과했습니다. 초기 실패 캡처는 이 보고서의 화면으로 사용하지 않습니다.

이 에뮬레이터는 하드웨어 가속이 없는 소프트웨어 실행 환경입니다. 삼성 Android 17/API 37 실기기에서의 배터리·발열·대규모 라이브러리 반응 속도는 직접 측정하지 못했습니다. 앱은 compile/target SDK 37로 빌드합니다. 이전 단계에서 실제 SoundCloud 검색·공개 스트림 연결을 확인했지만, 실행 환경의 YouTube 연결 제한 때문에 실제 YouTube 다운로드 성공을 이 보고서에서 주장하지 않습니다.
